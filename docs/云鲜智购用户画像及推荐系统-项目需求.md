## 1. 文档说明

### 1.1 编写目的

本文档描述「云鲜智购用户画像及推荐系统」的建设背景、技术架构、数据源、标签开发需求、推荐系统需求、调度与可视化需求、非功能需求及验收标准，作为：

- 开发者（大数据开发 / 数据挖掘）编码实现的依据；
- 使用 AI 辅助开发时，向 AI 提供上下文的**唯一事实来源**；
- 自测与验收的对照基准。

### 1.2 术语约定

| 术语 | 含义 |
|------|------|
| 用户画像 | 给用户打标签，即用户信息标签化；存储的是**标签 ID** 而非字符串 |
| 标签体系 | 3 级标签层级：行业 → 子行业 → 业务分类 → 场景（要开发的标签）→ 标签属性（贴到用户身上的值） |
| 2 级标签 | 一个"要开发的标签"（如"性别"），对应一个 Spark 计算任务 |
| 3 级标签 | 2 级标签的具体取值（如"男""女"），贴到用户身上的就是它 |
| 规则标签 / 匹配类 | 数据与规则直接匹配即可，无需聚合 |
| 统计类 | 需先按用户 ID 分组聚合，再按规则贴标签 |
| 挖掘类 | 需机器学习算法分类或预测 |
| 实时类 | 基于 Kafka + Structured Streaming 实时计算并更新 |
| 组合标签 | 由多个基础标签的 3 级标签组合而成的人群（如"高净值用户"） |

## 2. 项目背景与目标

### 2.1 公司背景

云鲜生鲜科技有限公司成立于 2016 年 7 月，黑马集团子品牌，以"甄选商品，服务到家"为宗旨，依托线上电商平台与线下社区门店提供全球优质生鲜产品。已形成门店、B2C 电商、批发、大客户团购、自营产品于一体的综合性生鲜平台，业务遍及全国 30 多个城市、超过 1300 家门店。

线上平台：<https://erabbit.itheima.net/#/>

### 2.2 项目背景

公司已完成**第一阶段离线数据仓库**建设，实现数据集中存储、统一管理和多维分析。为进一步理解用户、提升体验、实现营销精准化与业务增长，启动**第二阶段：用户画像及推荐系统**。

> 本方案为全行业通用解决方案，不限于电商：银行、保险、医疗、教育、金融等行业均适用同一架构与方法论（如银行场景：一级标签"银行"、二级标签"黑马"、三级标签"资产属性"、二级标签"资产金额/资产周期"、三级标签"10W/100W"）。

### 2.3 建设目标

1. **建标签**：建成 3 级标签体系，开发约 **200 个** 2 级标签（含匹配、统计、挖掘、实时四类）。
2. **建存储**：标签结果落 ES，支持按标签快速圈人（交/并/差集）；元数据落 MySQL。
3. **建调度**：离线任务用 DolphinScheduler 定时调度，实时任务提交 YARN 常驻。
4. **建应用**：面向画像 Web 平台（标签查询、微观画像、组合标签圈人）与推荐系统（多种推荐算法）提供数据服务。
5. **建推荐**：实现基于流行度、协同过滤（ALS / ItemCF / UserCF）、关联规则（FP-Growth）等推荐算法，结果落 Doris，并提供实时调用接口。

### 2.4 项目范围

**包含**：数据采集、标签计算（匹配/统计/挖掘/实时）、标签存储与合并更新、组合标签、推荐算法开发、调度配置、可视化对接。

**不包含**（由其他角色负责）：标签管理平台前端与后端开发（Java + Vue）、FineBI 报表具体看板设计、集群运维。

### 2.5 业务数据规模

| 指标 | 数值 |
|------|------|
| 用户量 | 1000 万 |
| 日活 | 线上 80 万 + 线下 45 万（线下只统计购买人数） |
| 门店数量 | 1300 家 |
| 门店日均单量 | 线上 100 单 + 线下 350 单 |
| 日均营业额 | 线上 5000 元 + 线下 10000 元 |

### 3.2 数据流设计

**（1）离线数仓链路（黑色链路）**
SeaTunnel 从关系库抽取 → Hive ODS 层 → HiveSQL 逐层计算 → ADS 层数据经 SeaTunnel 导入 Doris。

**（2）离线标签链路（紫色链路）**
两种方式并存：
- 基于数仓数据用 **Spark SQL** 计算 → 结果存 Hive → SeaTunnel 导出到 ES；
- 基于数仓数据用 **Spark Core / Spark MLlib** 计算 → 结果直接写 ES。

**（3）实时标签链路（蓝色链路）**
业务库数据经 SeaTunnel（MySQL CDC）、日志数据经 Flume 汇集到 Kafka → **Structured Streaming** 计算 → 中间结果回写 Kafka，最终结果写 ES 或 Doris。

**（4）交互式分析链路（绿色链路）**
Doris 除分析本地数据外，通过**联邦查询**分析 Hive、Elasticsearch、MySQL 中的数据，供交互式查询与可视化（FineBI）直接调用。

### 3.3 存储设计

**（1）Elasticsearch — 标签结果存储**

索引名：`user_profile_tags`，主键 `user_id`。

> ⚠️ **必须先手动建索引并指定逗号分词器，再写标签**。若让 ES 首次自动创建索引，`tags_id_times` 会被推断为 long 类型，后续写入字符串会报类型不匹配。

```
PUT user_profile_tags
{"settings": {"analysis": {"analyzer": {"comma": {"type": "pattern", "pattern": ","}}}}}
```

```
POST user_profile_tags/_mapping
{"properties": {
  "user_id":            {"type": "long"},
  "tags_id_once":       {"type": "text", "analyzer": "comma", "search_analyzer": "comma"},
  "tags_id_times":      {"type": "text", "analyzer": "comma", "search_analyzer": "comma"},
  "tags_id_streaming":  {"type": "text", "analyzer": "comma", "search_analyzer": "comma"}}}
```

三个标签字段的语义划分：

| 字段 | 适用标签 | 更新方式 |
|------|----------|----------|
| `tags_id_once` | 离线**一次性**更新（主要基于 Spark SQL，经 SeaTunnel 写入） | 整字段覆盖 |
| `tags_id_times` | 离线计算但**需多次更新**（Spark ML 与 Spark DSL） | 新老合并后覆盖 |
| `tags_id_streaming` | **实时**计算多次更新（Structured Streaming） | 新老合并后覆盖，另写 `{app_name}_time` 时间戳列 |

**（2）Doris — 结果与分析存储**

| 库名 | 用途 | 主要表 |

| `log_analysis_db` | 日志指标结果 | `nginx_log_result`、`user_event_result` |
| `db_analysis_db` | 订单窗口指标 | `user_12hours_analysis` |
| `recommend_db` | 推荐结果 | 见第 6 章 |

**（3）Hive — 数仓分层与标签中间结果**

| 库 | 用途 | 主要表 |
|----|------|--------|
| `dwm` | 会员/订单/商品主题宽表 | `dwm_sold_goods_sold_dtl_i`、`dwm_sell_o2o_order_i`、`dwm_mem_member_behavior_day_i`、`dwm_mem_first_buy_i` |

### 4.3 数据采集需求

**（1）离线全量同步（SeaTunnel）**

配置文件：`/export/server/apache-seatunnel-2.3.5/config/job/loadData.config`

- `env`：`job.name = "loadData"`、`execution.parallelism = 4`、`job.mode = "BATCH"`、`checkpoint.interval = 10000`
- `source`：5 个 `Jdbc`，URL `jdbc:mysql://up01:3306/hive_data?useUnicode=true&characterEncoding=utf8&useSSL=false`，`driver = "com.mysql.cj.jdbc.Driver"`，`user = "root"`，`password = "123456"`
  - 5 张表分别同步，`partition_column`：`dwm_sold_goods_sold_dtl_i` → `quarters`；`dwm_sell_o2o_order_i` → `quarters`；其余 3 张 → `zt_id`
- `sink`：5 个 `Hive`，`metastore_uri = "thrift://up01:9083"`
- 运行：`./bin/seatunnel.sh --config ./config/job/loadData.config -e local`

**（2）Hive → ES 同步**

配置文件：`config/job/hive2es.config`，Hive source + FieldMapper transform + Elasticsearch sink。

- 关键：Hive 侧字段名 `tags_id` 通过 `FieldMapper` 映射为 ES 的 `tags_id_once`
- `primary_keys = ["user_id"]`、`hosts = ["up01:9200"]`
- 分区参数：`read_partitions = ["dt=\"${pt}\""]`
- 运行：`./bin/seatunnel.sh --config ./config/job/hive2es.config -e local -i pt=2024-06-12`
- 报错处理：`rm -rf /tmp/seatunnel/imap` 后重跑

**（3）日志采集（Flume）**

| 配置文件 | 采集源 | Kafka Topic |
|----------|--------|-------------|
| `nginx_to_kafka.conf` | `/export/data/workspace/log_generate/datacollection/source_data/access-nginx.*` | `xtzg_nginx_log` |
| `user_event_to_kafka.conf` | `/export/data/workspace/log_generate/datacollection/source_data/user-event.*` | `xtzg_user_event` |

公共配置：`TAILDIR` source + `org.apache.flume.channel.kafka.KafkaChannel`，`bootstrap.servers = up01:9092`，`parseAsFlumeEvent = false`，位置文件 `/export/data/flume/*_position.json`。

启动：`bin/flume-ng agent -n a1 -c conf/ -f job/nginx_to_kafka.conf`
采集脚本：`/root/bin/flume-collect.sh {start|stop} {nginx|user_event}`

**（4）业务库实时采集（SeaTunnel MySQL CDC）**

配置文件：`config/job/shop_order_to_kafka.config`

- 采用**基于 Binlog 的 CDC**（底层原理同 Debezium）
- 前置：JDBC Driver 放 `lib/`；创建 MySQL 用户 `mysqlcdc`/`itcast` 并授权；MySQL 开启 binlog（`binlog_format=ROW`、`binlog_row_image=FULL`、`gtid_mode=on`）
- 关键参数：`base-url="jdbc:mysql://up01:3306/hive_data"`、`start.mode="initial"`、`server-time-zone="Asia/Shanghai"`、`table-names=["hive_data.shop_order"]`、`format = compatible_debezium_json`、`debezium{database.server.name="mysql_cdc"}`
- sink Kafka：`topic="test_topic"`、`bootstrap.servers="up01:9092"`
- Topic 命名规则：`mysql_cdc.hive_data.shop_order`（`database.server.name` 前缀 + 库表名）

| `rule` | 标签规则 |
| `level` | 标签级别 |

**2 级标签 rule 格式**（5 段式，段间用 `##`，键值用 `=`）：

```
inType=Hive##nodes=up01:9083##table=dwd.dwd_mem_member_union_i##selectFields=zt_id,birthday_date##range=all
```

| 键 | 含义 |
|----|------|
| `inType` | 存储介质。离线为 `Hive`，实时为 `Kafka` |
| `nodes` | 集群地址（Hive 用 9083；实时场景课件中仍写 9083） |
| `table` | 表名；**实时场景下该字段实际是 Kafka topic 名** |
| `selectFields` | 需要读取的字段 |
| `range` | 数据范围；实时场景下是 offset 策略（如 `earliest`） |

**3 级标签 rule**：记录匹配规则，形如区间 `0-7`、`8-14`，或枚举值。

> **核心约定：打标签打的是标签 ID，不是字符串。** 最终结果形如 `用户id → 1 8,16,20`。

create table ads.ads_mem_user_rfm_i  (user_id bigint, tags_id string) partitioned by (dt string);
create table ads.ads_mem_new_old_user_i (user_id bigint, tags_id string) partitioned by (dt string);
create table ads.ads_mem_tags_i (user_id bigint, tags_id string) partitioned by (dt string);
```

```sql
insert overwrite table ads.ads_mem_tags_i partition(dt)
select user_id, concat_ws(',', collect_list(tags_id)) as tags_id, '${inputdate}' as dt
from (select * from ads.ads_mem_user_rfm_i where dt = '${inputdate}'
      union all
      select * from ads.ads_mem_new_old_user_i where dt = '${inputdate}') t
group by user_id;
```

### 5.9 标签合并与更新机制（核心难点）

**问题**：同一用户身上"同一 2 级标签"下的旧 3 级标签值必须被新值替换，而不是累加。

**方案对比**：

| 方案 | 说明 | 结论 |
|------|------|------|
| 不同类型标签存不同字段 | 字段过多降低 ES 检索效率，圈人交并集条件复杂 | ❌ 不采用 |
| **单标签同一字段 + 新老合并后覆盖** | 每次与历史标签合并后整体覆盖 | ✅ **本项目采用** |

**合并算法**：
1. 给新标签数据加一列 `three_tags`（本次涉及的所有 3 级标签 id 拼接串，用 `F.lit()`）；
2. 与从 ES 读取的历史标签 `left join`；
3. 用 UDF `update_tags(new_tag, old_tags, three_tags)` 遍历历史标签，**剔除属于本次 3 级标签范围的 id**，再追加新标签；
4. 以 `upsert` + `es.mapping.id=user_id` 写回。

**需"全量用户"语义的标签特殊处理**（消费周期、客户价值）：
- 用 `full join`（不是 left join）+ `F.coalesce(old_df['user_id'], result_df['user_id'])`；
- 未覆盖到的用户补默认标签 id：消费周期补 `30`（90天以上），客户价值补 `46`（超低价值）。

### 6.1 推荐场景与算法清单

**推荐方式**：分离线推荐与实时推荐（实时推荐一般为离线跑好模型后部署服务）。

**本项目实现 5 类算法**：

| 序号 | 算法 | 类型 | 输出表 |
|------|------|------|--------|
| 1 | 近期热门商品推荐 | 基于流行度 | `recommend_db.popular_hot_goods` |
| 2 | 个人热门商品推荐 | 基于流行度 | `recommend_db.popular_person_hot_goods` |
| 3 | ALS 隐语义协同过滤 | 基于模型（矩阵分解） | `recommend_db.als_goods_for_user` |
| 4 | ItemCF 基于物品的协同过滤 | 邻域协同过滤 | `recommend_db.als_sim_goods_list` |
| 5 | UserCF 基于用户的协同过滤 | 邻域协同过滤 | `recommend_db.user_cf_goods_for_user` |
| 6 | FP-Growth 关联规则 | 关联规则 | `recommend_db.fpgrowth_association_goods` |

> 其他可扩展算法（了解）：基于内容推荐（CB）、基于模型的推荐（矩阵分解、分解机、深度学习）、组合推荐（加权/变换/混合/特征组合/特征扩充/元级别）。

### 6.3 基于流行度推荐

**（1）近期热门商品推荐**（`tags/recommend/popular_hot_goods_recommend.py`，appName `popular_hot_goods`）
- 输入：`dwm.dwm_sold_goods_sold_dtl_i`，近 30 天（`dt >= date_sub(current_date,30) and dt <= date_sub(current_date,1)`），排除 `zt_id != 0 and zt_id is not null`
- 计算：按 `goods_no, goods_name, third_category_no, third_category_name` 聚合 `count(order_no) as order_num` → `order by order_num desc limit 1000`；虚拟商品 id：`cast(concat('1', goods_no) as int) as id`
- 输出表 `recommend_db.popular_hot_goods`：UNIQUE 模型，`UNIQUE KEY(calculate_date, id)`，`PARTITION BY RANGE(calculate_date)`，`DISTRIBUTED BY HASH(id) BUCKETS 1`
- 字段：`calculate_date DATE`、`id INT`、`goods_no`、`goods_name`、`third_category_no`、`third_category_name`、`order_num INT`

**（2）个人热门商品推荐**（`tags/recommend/popular_person_hot_goods_recommend.py`，appName `person_popular_hot_goods`）
- 同源表近 30 天，按 `zt_id as user_id` + 商品维度聚合，用 `row_number() over (partition by user_id order by order_num desc)` 取 `rn <= 20`
- 输出表 `recommend_db.popular_person_hot_goods`：`UNIQUE KEY(calculate_date, user_id)`，`DISTRIBUTED BY HASH(user_id) BUCKETS 1`

### 6.4 基于 ALS 的隐语义协同过滤

**原理**：矩阵分解 R ≈ P(U×k) × Q(k×I)，使用 `pyspark.ml.recommendation.ALS`。

**评分构造**（本项目无历史评分日志，用业务库 + 日志结合）：
- 权重：浏览 1 分、加购 2 分、下单 3 分、支付 5 分、退单 -5 分
- 业务库：近 90 天 `dwm.dwm_sold_goods_sold_dtl_i`，
  ```sql
  select zt_id as user_id, goods_no,
         sum(if(trade_type in (2,5), -1, 1)) * 5 as score
  from dwm.dwm_sold_goods_sold_dtl_i
  where dt >= date_sub(current_date,90) and dt <= date_sub(current_date,1)
    and zt_id != 0 and zt_id is not null
  group by zt_id, goods_no
  ```
- 日志：`hdfs://up01:8020/xtzg_log/etl/dwd_user_event_etl_result/dt=YYYY-MM-DD`（ORC），取 `user_id`、`F.split('goods_name','=')[0].alias('goods_no')`，分数 `is_browse*1 + is_cart*2 + is_order*3 + is_buy*5 - is_back_order*5`
- 合并：`hive_df.unionAll(log_df).groupby('user_id','goods_no').agg(F.sum('score').alias('score'))`
- ⚠️ ALS 要求整型 ID：`F.concat(F.lit('1'), F.col('goods_no')).astype(IntegerType())` 加前缀 1

**训练与调优**：
- 划分：`randomSplit([0.8, 0.2], seed=88)`
- 模型：`ALS(userCol='user_id', itemCol='goods_no', ratingCol='score', coldStartStrategy='drop')`
- 评估：`RegressionEvaluator(metricName='rmse')`
- 超参调优（`get_best_parameter(df)`）：`ParamGridBuilder().addGrid(als.rank,[5,10,15]).addGrid(als.maxIter,[5,10,20]).addGrid(als.regParam,[0.01,0.05,0.1])`，`CrossValidator(numFolds=3)`，最佳参数经 `best_model._java_obj.parent().getRank()/getMaxIter()/getRegParam()` 获取
- **最终采用参数：`rank=15, maxIter=20, regParam=0.1`**，用全量数据 `als.fit(union_df)`
- 推荐：`recommendForAllUsers(10)`
- 结果加工：`TRANSFORM(recommendations, x -> named_struct('goods_no', substr(CAST(x.goods_no AS STRING),2), 'rating', x.rating))`

**输出表 `recommend_db.als_goods_for_user`**：`user_id INT`、`goods_nos STRING`；`UNIQUE KEY(user_id)`、`DISTRIBUTED BY HASH(user_id) BUCKETS 10`、`PROPERTIES("replication_num"="1")`

> **模型不持久化**，每次根据新数据重新计算。
> 代码文件：`tags/recommend/als_recommend.py`。

### 6.5 协同过滤（ItemCF / UserCF）

**（1）ItemCF 基于物品的协同过滤**
- 思路：用 ALS 训练出的 `itemFactors`（物品特征矩阵 V(I×K)），两两计算**余弦相似度**
- 步骤：`item_factors_df = als_model.itemFactors.select(F.expr("substr(cast(id as string),2) as goods_no"),'features')` → `crossJoin` 自关联 → UDF `consin_sim`（`np.dot` / `np.linalg.norm`，`round(...,4)`）→ 过滤 `simScore >= 0.75` → `groupBy('df1.goods_no')` + `collect_list` → `array_sort` 后 `slice(...,1,10)` 取 Top10 → 生成 `id = cast(concat('1',goods_no) as int)`
- 输出表 `recommend_db.als_sim_goods_list`：`id INT`、`goods_no STRING`、`sim_goods_list STRING`；`UNIQUE KEY(id)`、`DISTRIBUTED BY HASH(id) BUCKETS 10`

**（2）UserCF 基于用户的协同过滤**
- 思路：**从用户标签向量算相似度**（标签相近则人相似），找最相似 10 个用户，取其评分最高的商品并剔除目标用户已购商品
- 步骤：
  1. `spark = AbstractTagsBase.get_spark('user_cf_recommend')`
  2. `es_df = AbstractTagsBase.read_es(spark, fields='user_id,tags_id_times,tags_id_once,tags_id_streaming')`，用 `F.concat` + `F.coalesce` 合并三字段为 `tags`
  3. `F.split('tags',',')` + `filter(x -> x != '')` → `CountVectorizer` 二值化用户-标签矩阵
  4. 自连接 + UDF `consin_sim`，过滤 `cosine_sim >= 0.75`
  5. 每用户取最相似 10 个：`Window.partitionBy('user1').orderBy(F.col('cosine_sim').desc())` + `row_number()` + `filter('rn <= 10')`
  6. 每用户评分最高商品：`round(log(score),3) as score`、`rank() over(partition by user_id order by score desc)`、`where score > 0`、`rn <= 10`（近 90 天）
  7. 两次 join 后 UDF `calculate_score(cosine_sim, user1_goods_no, user2_goods_no)`：剔除已购，分数 = `item['score'] * cosine_sim`（保留 3 位）
  8. `explode` + `collect_list` → `array_sort` 后 `slice(...,1,10)`
- 输出表 `recommend_db.user_cf_goods_for_user`：`user_id INT`、`goods_nos STRING`；`UNIQUE KEY(user_id)`、`DISTRIBUTED BY HASH(user_id) BUCKETS 10`
- 开发提示：`user_df = user_df.sample(fraction=0.01, seed=66)`（开发用，上线注释掉 `show()`）
- 代码文件：`tags/recommend/user_cf_recommend.py`；**优化版** `tags/recommend/user_cf_recommend_optimize.py`

**UserCF 优化版要点**（性能优化需求）：
- 先用 `Normalizer(inputCol="features", outputCol="norm_features")` 标准化向量（范数为 1 时余弦相似度 = 点积）
- `to_dense` UDF 将稀疏向量转 array（`vector.toArray().tolist()`）→ `astype(ArrayType(FloatType()))`
- 用 `F.zip_with('f1','f2', lambda x,y: x*y)` + `F.aggregate('f3', F.lit(0.0), lambda acc,x: acc+x)` 求点积并 `F.round(...,4)`，**避免复杂 UDF**

### 6.6 基于关联规则的推荐（FP-Growth）

**原理指标**：
- 支持度 `support`
- 置信度 `confidence = support(A→B) / support(A)`
- 提升度 `lift = confidence(A→B) / support(B)`（>1 有效、=1 无关、<1 负相关）

**实现**：`pyspark.ml.fpm.FPGrowth`（比 Apriori 效率高）

- 输入：
  ```sql
  select order_no, collect_set(goods_no) as items
  from dwm.dwm_sold_goods_sold_dtl_i
  where dt >= date_sub(current_date,90) and dt <= date_sub(current_date,1)
    and zt_id != 0 and zt_id is not null
  group by order_no
  ```
- 参数：`FPGrowth(itemsCol="items", minSupport=0.0005, minConfidence=0.6)`
  > 两者越小，频繁项集/规则越多，召回率升高、准确率降低；一般 `minConfidence > 0.5`
- 模型输出：`freqItemsets`（`items`、`freq`）、`associationRules`（`antecedent`、`consequent`、`confidence`、`lift`、`support`）
- **模型持久化**：路径 `/model/fpGrowthModel`，用 `HdfsUtil().exists(path)` 判断 → `FPGrowthModel.load(path)` 或 `fpg_model.save("hdfs://up01:8020" + path)`
- 封装方法：`get_recommend_goods(goods_list, spark, model)`，调用示例 `goods_list = ['3215330']`
- 输出表 `recommend_db.fpgrowth_association_goods`：`calculate_date DATETIME`、`antecedent ARRAY<STRING>`、`consequent ARRAY<STRING>`、`confidence DOUBLE`、`lift DOUBLE`、`support DOUBLE`；`DUPLICATE KEY(calculate_date)`（冗余模型）、`DISTRIBUTED BY HASH(calculate_date) BUCKETS 1`
- 代码文件：`tags/recommend/fp_growth_recommend.py`，appName `fp_growth`

### 9.6 基类设计约定

**离线基类 `AbstractTagsBase`**（`metaclass=abc.ABCMeta`）

- 抽象方法：`get_parameter()`、`compute()`
- 通用方法：`execute`、`read_parameter`、`save_result`、`update_tags`、`write_es`(静态)、`read_es`(静态)、`read_rule_5`、`read_hive`、`read_rule_4`、`get_mysql`(静态)、`get_spark`(静态)
- `get_parameter` 返回值约定：`app_name`(str)、`rule_id`(int)、`condition`(可选)、`tags_field`(可选，默认 `tags_id_times`)
- `write_es` 默认参数：`nodes='up01'`、`index='user_profile_tags'`、`operation='upsert'`、`_id='user_id'`

**实时基类 `AbstractStreamingTagsBase(AbstractTagsBase)`**
- 抽象方法：`get_parameter()`（返回 `app_name, rule_id [, tags_field]`，默认 `tags_id_streaming`）、`compute(five_rule_df, kafka_df)`
- 重写 `execute`：读 MySQL rule → 读 Kafka → `json_tuple` 拆字段 → 读 3 级标签 → `compute` → `save_result`

**`RuleMeta`**（`tags/bean/rule_meta.py`）
- 字段：`inType`、`nodes`、`table`、`selectFields`、`range`
- 方法：`from_rulestr_to_esmeta(rule_str)`——`split('##')` → 逐项 `split('=')` → 组 dict → 构造 RuleMeta

## 11. 验收标准

### 11.1 功能验收

1. **标签正确性**：随机抽取用户，核对每类标签计算结果与源数据、业务规则一致；
2. **标签完整性**：ES `user_profile_tags` 中用户数与业务库一致，无大面积缺失；
3. **标签 id 规范**：存储的是标签 id 而非字符串；
4. **合并正确性**：重复执行同一标签任务，结果不重复累加（验证 `update_tags` 逻辑）；
5. **实时性**：实时标签在数据到达后能更新；
6. **推荐可用性**：6 张推荐结果表均有数据，推荐服务接口可正常返回；
7. **圈人可用性**：ES 交集/并集/差集查询结果符合预期，组合标签（高净值用户等）圈出人群合理；
8. **调度可用性**：DS 工作流按设定周期正常执行，失败重试生效。

### 11.2 非功能验收

按第 8 章指标逐项验证：页面响应 < 3s、并发 50、SQL 查询 < 3s、接口返回 < 3s。

### 11.3 验收方法

> 用户画像的验证可通过**上游推荐系统**和**标签本身逻辑的可靠性与完整性**两方面衡量。
