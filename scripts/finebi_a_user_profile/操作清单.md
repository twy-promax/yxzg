## 第 0 步：在 Doris 里执行视图脚本（只做一次）

```bash
mysql -h up01 -P 9030 -uroot -p < /export/data/workspace/user_profile/scripts/doris_scripts/finebi_dashboard_views.sql
```

执行完跑一下自检（脚本末尾有注释版的语句）：

```sql
SELECT * FROM recommend_db.v_a01_sex ORDER BY 排序;
-- 期望三行：5 男 1845 / 6 女 4324 / 7 未知 15039
SELECT * FROM recommend_db.v_a00_kpi;
-- 期望：用户总数 21208、标签值总数 82、标签类别数 17
```

**以后每次标签跑完批，只要重跑脚本「第二节」那两条刷新语句（`TRUNCATE TABLE` + `INSERT INTO`）就行**，视图不用重建。

> ⚠️ 这里**不能用 `INSERT OVERWRITE`**：本项目 Doris 1.2.1 的 `INSERT OVERWRITE` 只支持分区表，`user_tag_long` / `user_tag_stat` 是非分区表，用它直接报语法错误（已实测）。


## 第 2 步：图表通用配置（每个组件都这么设）

所有 A 视图的输出都是同样三列，所以配置套路完全一致：

| 设置项 | 怎么设 |
|---|---|
| **维度** | 拖「标签值」 |
| **指标** | 拖「用户数」，聚合方式选 **求和** |
| **排序（关键）** | 把「排序」也拖进维度（1:1 对应「标签值」，不会拆散数据），点它的下拉 → **升序**；然后把它在图上隐藏 |
| **图例/标签** | 建议打开「显示数值」和百分比 |
| **配色** | 用同一套色板；客户价值那块可以单独用渐变色强调 |

> ⚠️ 为什么必须手动设排序：FineBI 不保留视图里的 `ORDER BY`。你的性别组件预览顺序是 6→7→5（而不是 5→6→7），就是这个原因。

## 第 4 步：全局样式与刷新

| 项 | 设置 |
|---|---|
| 画布 | 仪表板设置 → 尺寸选**固定** 1920×1080 |
| 主题 | 深色背景（更接近"大屏"观感），文字用浅色 |
| 网格 | 打开对齐网格，方便排布 |
| **刷新** | 组件级设置：A01–A14 **每天 1 次**（跟标签跑批时间走，别设实时）；A16/A17 可以 5~10 分钟 |
| 标题栏 | 用文本框写"数据截止时间"，或用 `v_a00_kpi.数据更新时间` 做一个小指标卡 |

> 画像标签是离线 T+1 的，把它设成秒级刷新只会误导观众"数据在变"。

## 第 5 步：验收自检

- [ ] KPI 四张卡分别是 **21208 / 21208 / 82 / 17**（已打标用户数若小于总数，说明有用户一个标签都没打上，属正常）
- [ ] 性别是 **男 1845 / 女 4324 / 未知 15039**，与第 0 步 SQL 结果一致
- [ ] 每个图的横轴/扇区顺序是业务顺序（年龄段是 50后→20后，消费周期是 近7天→90天以上）
- [ ] 客户价值 7 档从「超高价值」到「超低价值」依次排列
- [ ] 所有组件底部没有出现 FineBI 的报错提示
- [ ] 打开一次"预览/分享"链接，确认在 1920×1080 下无滚动条

## 上屏前的数据预期（避免误判成 bug）

- **A12 活跃度**：约 94% 用户是「非常不活跃」—— 文档档位按 90 天活跃度设计，样本撑不起来。
- **A15 USG**：约 99% 是「中性」—— 依赖的 10 个特征编码在数据源里不存在。**建议不建这个数据集。**
- **A13 PSM**：有两条实现路线并存（统计类 + 挖掘类），都写同一批 id，**最终值取决于哪条后跑**。
- **A16/A17 实时**：覆盖用户数远少于离线标签，图上人少是正常的。
